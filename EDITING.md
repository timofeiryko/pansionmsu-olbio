# Как редактировать презентацию

## Что редактировать

Исходник первой лекции — **`1-intro/index.html`**. Оформление — `1-intro/styles.css`; фотографии и видео — `1-intro/assets/`.

`olympiad-biology.html` — собранная автономная копия для показа. Её лучше пересобирать после правок исходника: `python package.py`. Корневой `index.html` только перенаправляет к лекции.

## Быстро исправить текст прямо на GitHub

1. Откройте [исходник первой лекции](https://github.com/timofeiryko/pansionmsu-olbio/blob/main/1-intro/index.html).
2. Нажмите карандаш **Edit this file**.
3. Найдите нужную фразу через поиск и исправьте текст между HTML-тегами.
4. Нажмите **Commit changes** и сохраните изменение в `main`.
5. Дождитесь успешного `pages build and deployment` во вкладке Actions, затем обновите [сайт](https://timofeiryko.github.io/pansionmsu-olbio/1-intro/).

Примеры:

```html
<h3>Адаптации формируются в ходе <strong>эволюции</strong></h3>
<p>Обычный текст, <em>курсив</em> и <a href="https://example.org">ссылка</a>.</p>
<ul>
  <li>Первый пункт</li>
  <li class="fragment">Этот пункт появится после нажатия стрелки</li>
</ul>
```

`<strong>` — жирный, `<em>` — курсив, `<li>` — пункт списка. Сохраняйте окружающие `class` и `data-fragment-index`: они задают оформление и порядок появления.

Если после правки на GitHub хотите продолжить локально, сначала выполните `git pull`. Локальная копия сама не обновляется после редактирования в браузере.

## Редактировать локально

1. Откройте папку проекта в VS Code или другом редакторе HTML.
2. Измените `1-intro/index.html`, сохраните Ctrl+S.
3. Откройте этот файл в браузере и обновите страницу. Для режима докладчика используйте `serve.ps1` и `http://127.0.0.1:8766/1-intro/`.
4. Для автономного HTML и ZIP выполните `python package.py` из корня проекта.
5. Проверьте изменённые слайды, затем отправьте правки на GitHub:

```powershell
git add 1-intro/index.html
git commit -m "Update lecture text"
git push
```

При изменении оформления или изображений также добавьте соответствующие файлы из `1-intro/styles.css` и `1-intro/assets/`.

Новый слайд: скопируйте похожий `<section class="slide">`, задайте уникальный `id`, обновите `data-title`, заголовок и содержимое. Номер слайда и список переходов пересчитаются сами. Не удаляйте `<footer class="slide-foot"><span></span></footer>`: это номер без подписи курса.

## Pinegrow и TinyMCE: что подходит

### Pinegrow — готовый визуальный редактор HTML

Pinegrow открывает существующие HTML/CSS-файлы и позволяет визуально править текст и элементы страницы. Для нашего проекта надо открывать **локальную папку**, затем `1-intro/index.html`, сохранять HTML и проверять результат в обычном браузере. Сохранение файла и публикация на GitHub — отдельные шаги.

Он подходит, если хочется редактировать и текст, и расположение блоков в готовой программе. Но интерфейс рассчитан на сайты. Совместимость именно с нашей презентацией не проверялась: Reveal масштабирует холст и скрывает неактивные слайды, поэтому возможность редактировать нужный слайд необходимо проверить на копии перед выбором программы.

Документация: [открытие существующего HTML и устройство редактора](https://pinegrow.com/docs/getting-started/quick-intro-to-the-pinegrow-web-editor/), [работа со страницами и сохранение](https://pinegrow.com/docs/pages/pages.html).

### TinyMCE Inline — компонент для встроенного режима редактирования

Для сценария «нажал на текст, выделил слово жирным, дописал список» этот подход лучше соответствует нашей задаче. Inline-режим правит существующие блоки и использует стили презентации; сетку и размеры можно оставить под контролем шаблона.

**В текущую версию редактор не встроен.** TinyMCE предоставляет ввод и форматирование текста, но полноценный режим для нашей презентации требует также:

- отключать горячие клавиши Reveal во время набора текста;
- редактировать только текстовые области, сохраняя структуру слайда и fragments;
- сохранять чистый HTML без временных атрибутов Reveal и самого редактора;
- отдельно решить скачивание изменённого файла и обновление GitHub Pages.

На GitHub Pages нет серверного обработчика сохранения. Кнопка «Сохранить HTML» могла бы скачать локальный файл; опубликованный сайт от этого автоматически не изменится. Нужен commit/push или отдельная авторизованная интеграция.

TinyMCE распространяется с вариантами GPL и коммерческого лицензирования; это необходимо выбрать при интеграции. [Inline-режим](https://www.tiny.cloud/docs/tinymce/latest/use-tinymce-inline/), [лицензирование](https://www.tiny.cloud/docs/tinymce/latest/license-key/).

**Вывод:** для небольших правок уже сейчас проще редактировать исходник на GitHub. Для регулярных правок текста без HTML удобнее встроенный режим на основе TinyMCE; для свободной визуальной перестройки слайдов можно оценить Pinegrow на копии проекта.
